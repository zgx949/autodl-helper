# 使用指南

[返回首页](../README.md) · [安装指南](INSTALLATION.md) · [常见问题](FAQ.md)

## 一键开始

登录 AutoDL 并打开[个人账户 Pro 实例列表](https://www.autodl.com/console/instance/pro/list)，在希望开启的实例旁点击“抢机”。

脚本自动读取当前页面的登录信息、实例 ID 和名称。默认设置是：

| 设置 | 默认值 |
| --- | --- |
| 开始方式 | 立即尝试 |
| 库存不足后的重试间隔 | 60 秒 |
| 最多尝试次数 | 0，表示不限 |
| 微信通知 | 关闭 |

点击后不会要求再填写表单，也不会强制打开面板。原实例行直接显示任务进度。添加任务前请确认该实例确实是希望开机的目标；开机可能产生 AutoDL 正常使用费用。

## 查看进度

### 实例行

运行中的实例会显示：

- 当前状态，如“正在抢机”“等待重试”或“等待开始”。
- 已尝试次数。次数在发送一次开机请求时增加，不包含面板读取或倒计时刷新。
- 下次尝试倒计时。倒计时结束表示准备执行，后台节流或休眠可能造成延迟。
- “停止”按钮。

再次点击活跃任务的“查看进度”会打开任务面板，不会重复创建任务。任务结束后，是否能重新抢机由页面当前实例状态决定：实例已关机时可直接重新抢机；页面显示已运行或启动中时不能新增任务。历史“开机已受理”只是上一次请求的结果，不会永久阻止同一实例再次使用。

结束记录旁提供“删除记录”，无需先打开面板即可清理；活跃任务仍提供“停止”。

### 任务面板

点击右下角“抢机任务”，可以集中查看全部任务。进行中的任务优先展示，每个任务显示尝试次数、下次重试时间、最近结果和停止入口。

“添加实例”区域列出从当前页面识别到的实例，也可以直接点击“抢机”。已有活跃抢机任务的实例不再重复添加；页面显示已运行或启动中的实例不可新增任务。实例关机后，即使上次记录为“开机已受理”，也可以再次添加。

界面通常每几秒刷新快照，倒计时每秒更新。点击“刷新”只更新显示，不会额外发送开机请求。进度条表示任务正在等待或执行，不表示库存获取成功率或确定的完成百分比。

## 状态说明

| 显示状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 准备抢机 / 正在尝试 | 已创建任务或正在等待开机接口响应 | 等待结果 |
| 等待开始 | 按高级设置预约了未来时间 | 保持页面打开，等待开始 |
| 等待库存 / 等待重试 | 明确无库存，或服务暂时异常，等待下次尝试 | 可继续等待或停止 |
| 开机已受理 | 上一次开机请求被明确接受，轮询已停止 | 到控制台确认当前状态；之后关机可直接重新抢机，也可删除此记录 |
| 已停止 | 手动停止，或页面重新加载后暂停 | 如需继续，确认状态后点“重新抢机” |
| 需要处理 / 需检查 | 鉴权、业务、网络或服务连续异常导致任务停止 | 查看最近结果及运行记录，处理原因后重试 |
| 次数已用完 | 已达到设定的最多尝试次数 | 按需修改高级设置后重新添加 |

“开机已受理”不是“机器已经完成启动”。脚本不在成功响应后持续查询实例运行状态，也不会仅凭“没有库存不足提示”就判断成功。

## 停止、重试与删除

### 停止

在原实例行点击“停止”，或在面板点击“停止任务”。脚本取消后续重试，并尝试中止当前浏览器请求。

**已经发送到 AutoDL 的请求仍可能被处理。** 尤其是在请求刚发送时停止，或出现网络超时的情况下，请先查看控制台，不要把停止按钮当作撤销开机。

### 重新抢机

实例尚未开机且没有活跃抢机任务时，可点击“抢机”或“重新抢机”。上一次记录无论是已受理、已停止、错误还是次数耗尽，都不会永久限制重新开始。这会按**当前已保存的高级设置**创建新一轮尝试，次数从 0 重新计算。

例如：抢机成功后在 AutoDL 中关机，等页面状态更新为已关机，就可以直接再次点击“重新抢机”，**无需先删除上次成功记录**。页面明确显示已运行或启动中时不能新增抢机任务；仍在等待库存的活跃任务只提供进度查看和停止，避免重复创建。

### 删除记录

已受理、已停止、错误和次数耗尽等结束记录，都可以在原实例行点击“删除记录”，或在任务面板点击“删除记录”。活跃任务需要先停止，再删除记录。

删除只移除脚本中的任务记录，不会删除、释放、开启或关闭 AutoDL 实例，也不会影响其他实例的抢机任务。记录删除后，实例行不再显示该记录的历史进度；仍可按实例当前状态再次添加任务。运行记录中已有的历史消息可通过“运行记录 → 清空记录”另外清理。

## 高级设置

在“抢机任务”面板中展开“高级设置”。常用流程无需打开此区域。

### 新任务设置

| 选项 | 范围与行为 |
| --- | --- |
| 开始时间 | 留空立即开始；否则选未来时间，最远支持未来一年；使用电脑本地时间 |
| 重试间隔 | 30–86400 秒的整数，默认 60 秒 |
| 最多尝试 | 0–100000 的整数；0 表示不限，1 表示只尝试一次 |

修改后点击“保存设置”，设置才会用于之后添加的任务。它不会自动开始任何任务，也不会改变正在运行的任务。要调整现有任务，请先停止，再重新添加。

预约时间适用于之后按这些默认值添加的任务，并不是每天重复的日程。保存的预约时间已经过去后，新添加的任务会立即开始。

#### 示例：预约今晚开始等待库存

1. 展开高级设置，把开始时间设为今晚的目标时间。
2. 按需填写重试间隔和最多尝试次数，保存设置。
3. 回到实例行，在目标实例旁点击“抢机”。
4. 确认任务显示“等待开始”和对应倒计时。
5. 保持执行任务的标签页和电脑运行。

#### 示例：只尝试三次

把“最多尝试”设为 `3` 并保存，再添加目标实例任务。若三次均未受理，任务结束并显示“次数已用完”。如果第一次或第二次已被受理，则立即结束，不会补齐三次。

### 微信通知

1. 准备自己的 [WxPusher](https://wxpusher.zjiecode.com/) SPT。
2. 在高级设置的“微信通知”中填写，点击“保存通知”。
3. 如游猴询问访问推送域名，请根据自己的通知需求授权。
4. 开机请求被明确受理后，脚本会向 WxPusher 发送实例名称、ID 和受理消息。

SPT 只保存在当前页面内存中，**刷新或重新打开页面后需要重新填写**。点击“清除”可关闭本页后续的微信通知。不要把 SPT 粘贴到公开 Issue 或截图中。

只有推送服务返回确认成功，运行记录才会显示“微信通知已发送”。发送失败不会改变开机受理记录，也不会重新开机。浏览器通知和微信通知是不同渠道；浏览器或系统通知权限也会影响通知展示。

### 手动添加实例

通常不需要填写实例 ID。页面无法识别实例时，可在高级设置中的“手动添加实例”填写有效的 `pro-…` ID，再点击“抢机”。例如 `pro-demo0001` 仅为格式示例，不对应真实实例。

手动添加仍要求已登录的个人账户及有效权限，不会绕过 AutoDL 的鉴权，也不能用于新建实例或子账户接口。

## 重试与停止规则

一次请求结束后才安排下一次，不会并发重复请求同一实例。重试间隔从上次响应处理完成后计算，因此相邻请求开始时间可能大于设置值。

| 接口或网络结果 | 脚本处理 |
| --- | --- |
| HTTP 成功且业务码精确为 `Success` | 记录“已受理”，停止轮询并发送结果通知 |
| `InternalError` 且明确提示“当前算力规格暂无库存” | 按设置间隔重试 |
| HTTP 429 | 延长重试间隔，并参考 `Retry-After` |
| HTTP 5xx | 延长重试间隔；与限流一样，连续 5 次异常后停止 |
| HTTP 401 / 403 或已识别的鉴权失效码 | 停止当前页面的活跃任务，要求重新登录 |
| 余额不足、未知业务错误或其他无法识别的响应 | 停止任务并保留最近结果 |
| 网络错误或 20 秒请求超时 | 结果未知，停止任务，等待用户确认控制台状态 |

请求期间账户切换或退出登录时，原账户任务会停止。已发出的请求不保证能被撤销。浏览器从休眠或后台恢复后，不会连续补发错过的轮次。

## 页面、多标签与数据

### 保持页面运行

任务依赖打开的 AutoDL 页面。关闭执行任务的标签页、退出浏览器或电脑休眠都会中断正常执行。后台标签页可能被浏览器节流，不能保证秒级准点。

刷新或重新打开页面会保留任务记录，并暂停原来的活跃任务；确认实例状态后再手动重新启动。脚本不会在页面恢复时静默发送历史任务的开机请求。

### 多标签页

同一浏览器环境中，只有一个已加载脚本的 AutoDL 控制台标签页持有管理锁。其他标签页显示只读状态，可查看进度但不能开始、停止或修改任务。

如需换页管理：先停止需要停止的任务，关闭原管理页，再刷新希望接管的页面。不同浏览器、浏览器配置文件或不同脚本管理器的隔离环境不应被当作一个统一任务队列。

### 数据保存

- 游猴存储保存默认设置、已识别实例、任务配置与状态、关联账户标识，以及最多 150 条脱敏运行记录。
- 脚本读取的登录鉴权和用户填写的 SPT 不额外持久化；AutoDL 网站本身的登录信息仍由网站保存。
- 最多同时运行 20 个实例任务，最多保存 100 条任务记录；达到上限时先清理不需要的记录。
- 清空运行记录只删除脚本日志，不影响任务和 AutoDL 实例。

有关权限与敏感信息反馈，请参阅 [SECURITY.md](../SECURITY.md)。
