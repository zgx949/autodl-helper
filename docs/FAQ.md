# 常见问题

[返回首页](../README.md) · [安装指南](INSTALLATION.md) · [使用指南](USAGE.md)

## 页面没有出现“抢机”按钮

按顺序检查：

1. Tampermonkey 和 AutoDL Helper 脚本都已启用。
2. Chrome 扩展详情中已按要求允许用户脚本运行，并允许游猴访问 AutoDL。
3. 当前页面是 `https://www.autodl.com/console/…`，实例列表使用[个人账户普通页面](https://www.autodl.com/console/instance/list)或 [Pro 页面](https://www.autodl.com/console/instance/pro/list)。
4. 安装的是完整 `autodl-scheduler.user.js`，包括顶部元数据，没有把 `src/` 模块单独复制进去。
5. 安装或更新脚本后已刷新 AutoDL 页面，且实例列表已加载。
6. 没有同时启用旧副本或其他会改动实例表格的同类脚本。

如果右下角有“抢机任务”，但实例行没有按钮，脚本可能已加载而页面结构与当前识别方式不符。可先查看是否能在面板识别到实例；必要时使用高级设置中的手动实例 ID 备用入口，并按下方说明提交脱敏问题报告。

## 点击安装链接只看到源码

这通常表示浏览器没有把 Raw 文件交给游猴处理。请使用[手动复制安装](INSTALLATION.md#方式二手动复制安装)，不要把源码直接粘贴进浏览器控制台执行。

## 面板显示“请先登录 AutoDL”

脚本从当前页面读取登录状态，不需要手动抓包或填写 Authorization。请先登录个人账户，打开实例列表，再刷新页面。

如果 AutoDL 本身也要求重新登录，先完成网站登录。不要把鉴权请求头或 Cookie 发到 Issue 让别人代填。

## 显示“当前标签页只读”

请更新到 **1.2.3 或更新版本**，并刷新所有已打开的 AutoDL 标签页。旧版会把未持锁页面设为只读，导致“重新抢机”和“删除记录”同时变灰；普通与 Pro 页面都会受影响。

新版允许在其他标签页操作，由持有管理锁的页面统一执行。执行页关闭后，等待中的页面自动接管，旧活跃任务暂停；确认实例状态后可重新抢机。

若新版仍提示只读，请查看面板原因：持锁页面可能仍运行旧版、被浏览器冻结或通信不可用。返回执行页操作，或关闭旧页面后等待当前页接管。超时操作不会自动重发，请先确认任务与实例状态再手动重试。

## 浏览器提示缺少标签页互斥锁

脚本需要 Web Locks 支持。请更新 Chrome 并重新打开页面；不支持时脚本只展示界面，不会继续发起开机任务。

## 页面上的实例 ID 需要自己填写吗？

不需要。点击实例行的“抢机”会自动使用该行的 ID 和名称。高级设置中的手动 ID 仅在页面识别失败时备用。

## 为什么没有提供购买或新建实例？

当前版本针对已有个人账户普通与 Pro 实例的开机接口，只做库存不足后的重复尝试。创建、租用、释放、关机以及子账户接口属于不同操作流程，不在当前支持范围内。

## “开机已受理”之后，机器怎么还没运行？

“已受理”表示开机接口返回了明确成功，实例可能仍在启动过程中。脚本在此时停止轮询，不会把请求受理当作实例运行状态查询结果。

请到 AutoDL 控制台查看实例。不要仅因页面暂未更新就立即再次提交开机请求。

## 标准实例提示 GPU 不足后为什么停止了？

请更新到 **1.2.1 或更新版本**。1.2.0 沿用了 Pro 的业务码限制，部分标准接口的缺卡提示会被误判为错误。

新版对标准实例按明确的 GPU/显卡缺卡或库存不足提示持续重试，不再限定为 `InternalError`。默认每 60 秒尝试一次、次数不限，直到开机受理或手动停止。若希望一直等库存，请确认高级设置中的“最多尝试”保持为 `0`。更新后刷新实例页面，重新点击“抢机”即可；此前停止的任务不会自动恢复。

## 抢机成功后又关机，为什么不能重新抢？

请更新到 **1.1.1 或更新版本**。早期版本会让历史成功记录一直显示“查看结果”，导致已经关机的实例无法直接重新抢机，这个限制已修复。

现在按页面当前实例状态判断：实例已关机且没有活跃抢机任务时，保留上次“开机已受理”记录也能直接点“重新抢机”，无需先删记录。页面显示已运行或启动中时不能新增任务；若页面状态尚未更新，先确认 AutoDL 控制台的实际状态。

## 抢机记录在哪里删除？

任务结束后，原实例行有“删除记录”，任务面板中也有“删除记录”。已受理、已停止、错误或次数耗尽的记录都可以清理；活跃任务需先停止。

删除记录只清理本脚本中的任务信息，不会删除、释放、开启或关闭机器，也不会取消其他实例的任务。删除后若实例仍未开机，可以再次点击“抢机”。运行日志可在“运行记录”中单独清空。

## 任务为什么突然停止了？

打开“抢机任务”查看最近结果，必要时展开“运行记录”。常见原因包括：

- 页面刷新、关闭后重新打开，原活跃任务按设计暂停。
- 账户退出、切换或鉴权失效。
- 达到了设定的最多尝试次数。
- 余额不足或接口返回未识别的业务错误。
- 网络错误、请求超时，结果无法确认。
- 连续 5 次限流或服务异常。

先处理具体原因并确认控制台状态，再点击“重新抢机”。详情见[状态与重试规则](USAGE.md#重试与停止规则)。

## 超时后为什么不自动继续重试？

网络超时不能证明服务端没有收到开机请求。为了避免在结果不明时补发，脚本停止任务，要求用户先确认控制台状态。

## 点了“停止”，实例还是启动了

停止按钮会取消后续重试并尝试中止浏览器请求，但不能保证撤回已经送达 AutoDL 的请求。如果服务端已收到请求，仍可能完成启动。是否需要进一步操作，请在控制台确认。

## 预约时间到了却没有立刻执行

先检查任务是否仍为活跃状态、电脑时间和时区是否正确，以及是否使用执行任务的标签页。浏览器后台节流、标签页冻结、电脑休眠或网络状况都会造成延迟。

这是网页脚本，没有浏览器外的独立调度进程。它不保证秒级抢点，也不会在恢复时成批补发错过的尝试。

## 修改间隔后，已有任务为什么没有变化？

高级设置是**新任务的默认值**。保存后只影响之后添加的任务，不会重排当前任务。需要调整某个运行中的任务时，先停止，再重新添加。

## 预约设置是每天执行吗？

不是。开始时间是一个具体的本地日期和时间，用于之后添加任务的首次尝试。预约时间已过去时，新任务按立即开始处理。当前没有每天、每周等周期日程。

## 微信通知没有收到

1. 确认任务确实显示“开机已受理”；无库存重试时不会发送微信。
2. 确认在当前执行任务的页面填写了有效 SPT，并点击“保存通知”。
3. 如果刷新过页面，需要重新填写 SPT。
4. 检查游猴是否允许访问 `wxpusher.zjiecode.com`，并在 WxPusher 中检查自己的接收配置。
5. 查看运行记录是“微信通知已发送”还是“微信通知未发送成功”。

浏览器系统通知和微信通知互不等同。微信发送失败不代表开机失败，也不会触发另一次开机。请不要在公开反馈中粘贴完整 SPT 或含密钥的请求地址。

## 刷新后设置还在，但任务没有继续

这是预期行为。默认设置和任务记录保存于游猴存储中；执行状态需要在新页面中重新确认后手动启动，避免刷新页面后静默重发开机请求。SPT 仅在页面内存中，不会随记录恢复。

## 可以多开浏览器提高成功率吗？

脚本不提供跨浏览器协调。不同浏览器或配置文件可能各自持有独立状态，不会由同一把标签页锁协调。建议只保留一个管理页面，避免重复请求和互相矛盾的状态。

## 如何彻底关闭脚本？

先在页面停止任务，再到游猴停用或删除脚本，最后刷新 AutoDL 页面。只切换游猴开关，不应被当作对已经发出请求的撤销。

## 如何反馈问题？

在 [Issues](https://github.com/zgx949/autodl-helper/issues) 提供：

- 脚本版本、浏览器版本、Tampermonkey 版本。
- 页面类型与清晰的复现步骤。
- 预期行为、实际行为及脱敏后的错误文字。
- 如与布局有关，可提供隐藏实例标识和账号信息的截图。

不要提交完整保存页面、Cookie、Authorization、SPT、个人账户信息或含凭证的网络请求。敏感漏洞请按 [SECURITY.md](../SECURITY.md) 处理。
